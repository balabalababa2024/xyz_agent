# preference-notes

把用户说过的偏好与决策沉淀成记忆，并按类别决定投递策略。**偏好永不被上下文淘汰，决策按需检索，临时报错不记录。**

## 分类规则

| 类别 | 判据 | 存储 |
|---|---|---|
| 偏好 | 稳定、跨会话有效的主观要求（风格、格式、语言、禁忌、常用路径/工具） | `domain="hot"`、`memory_kind="profile"`、`delivery_policy="always"` |
| 决策 | 对某个项目/任务做出的长期选择（方案、命名、目录、流程） | `domain="fact"`、`memory_kind="fact"`、`delivery_policy="retrieved"` |
| 错误 | 一次性报错、临时环境异常、当天故障 | **不写** |

判据优先级：宁可少记，也不要把一次性指令当长期偏好。不确定时先不写，等用户重申。

## 偏好流程

1. **去重**：先 `memory_list(domain="hot")` 或在上下文中确认是否已有等价条目；同义重复不写，只在旧条目需要修正时用新内容覆盖（`memory_ingest` 同 `subject` 会更新）。
2. **写成自包含句**：包含主语与适用范围，例：
   - ✅ “用户要求所有回复使用简体中文（代码与报错原文除外）”
   - ✅ “用户习惯把成品放在仓库根目录下的 `out/`”
   - ❌ “喜欢中文”
3. **写入**：命中触发词的偏好在模型调用前已由 `pref_guard` 插件自动写入（`source="pref_guard"`），此时只需确认，不要重复写。只有用户明确说“记住这条”且 `memory_list(domain="hot")` 里没有等价条目时，才手工调用：

   ```text
   memory_ingest(content="<自包含句>", domain="hot", memory_kind="profile",
                 delivery_policy="always", subject="<简短主题>")
   ```

4. **确认**：只回一句“已记住：<要点>”。不要复述工具输出、不要解释热记忆机制。
5. **验证异常**：工具返回 `ERROR:` 时告知用户“这条偏好这次没存上”，不要假装已记住。

## 决策流程

```text
memory_ingest(content="<项目>: 采用 <方案>，原因是 <一句>", domain="fact",
              memory_kind="fact", delivery_policy="retrieved", subject="<项目>-决策")
```

决策不写 hot：只在相关话题出现时按检索注入，避免挤占每轮上下文。

## 边界

- 密钥、token、密码、身份证号等敏感内容永不写入记忆。
- 系统状态类描述（“今天沙箱挂了”“模型 503”）不写。
- 用户说“忘掉 X”：用 `memory_list` 找到对应条目，再按记忆页面的删除/拒绝方式处理；做不到就明确说无法删除。
- 与当前指令冲突时，当前指令优先；用户再次重申后覆盖旧偏好。
- 写入后如果用户马上又说“就这一次”，把它降级为决策（retrieved）或直接删除。
